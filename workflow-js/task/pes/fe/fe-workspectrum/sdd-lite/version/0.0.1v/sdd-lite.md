# [SDD-lite] FE 양식 정의

> 풀 SDD 이전의 약한 버전. **변경 사실 + 작업 체크리스트 + 검증 절차** 3축으로 압축.
> FE에서의 주된 용도: BE↔FE 계약 인계 수신·확정(예: 새 endpoint 소비 시점), Feature 도메인 간 어댑터(공유 hook·query key) 통일, 첫 stage 배포 검증 Runbook.

---

## 사용 시점 (트리거)

다음 조건 중 **2개 이상**을 만족할 때 본 양식을 쓴다.

- [ ] 변경 사실을 **다른 저장소/팀에 인계** 또는 그 인계를 **수신·확정**해야 함 (BE→FE 핸드오프 응답, 디자인 시스템 핸드오프)
- [ ] 여러 Story 묶음의 결과를 **한 번에 검증할 Runbook**이 필요 (마일스톤 종료 검증, 첫 stage 배포 검증)
- [ ] **호출 가능 / 호출 금지 endpoint 인벤토리**를 화이트리스트로 정리해야 함 (백엔드가 노출 미정 Port가 섞임)
- [ ] **응답 계약**을 명세화해야 함 (ApiResponse 래퍼, ErrorCode 분기, 헤더 X-Request-Id, 쿠키 매체)
- [ ] PES만으로는 부족하지만 풀 SDD까지는 과함 — 라우팅 그래프·실패 모드 매트릭스·CI/CD 단계가 **부분적으로만** 필요

**졸업 신호 → sdd(풀)로**:
- Product 단위 의도·아키텍처가 흔들리는 큰 결정 필요 (대안 검토 3+, 컴포넌트 트리·상태 흐름 다이어그램)
- 인프라(CloudFront 분리 / GHA 파이프라인 재설계) + FE 도메인 변경이 한 묶음으로 진행
- 1~2개월 이상의 FE 재설계로 확장

### 섹션 가이드

| 섹션 | 핵심 |
| --- | --- |
| **Context** | 받는 측이 FE 코드를 안 봐도 작업 완수 가능하도록 자기 완결적으로 |
| **진실 소스** | 본 문서가 옛 정보일 수 있다는 사실을 명시 + 결정적 시점 확인할 코드 경로 |
| **인벤토리** | "호출 금지" 박스는 명시적으로. endpoint 모듈을 만들면 dead code가 됨 |
| **계약** | JSON 예시 박스 — 추정 필드는 "추정"으로 태깅 |
| **작업** | 4축(path/what/why/check) 강제. 어느 하나라도 빠지면 받는 측 실행 불가 |
| **Runbook** | 명령 + 기대 응답 + 통과 신호 체크리스트 |
| **자가 점검** | 작성자 본인이 4 신호로 통과 여부 확정 |
