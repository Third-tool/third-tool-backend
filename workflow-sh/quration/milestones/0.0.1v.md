## [0.0.1v-01] GHA → AWS OIDC AssumeRole 전환  `[auth-security · infra-deployment]`

**훅**: long-lived AWS access key를 폐기하고 1시간 TTL 임시 자격증명으로 전환

**S (상황)**: GitHub Actions에서 AWS 자원 접근에 long-lived `AWS_ACCESS_KEY_ID`/`SECRET` 사용. 키 유출 리스크 · 순환 비용 · 감사 어려움.
**T (과제)**: key 없이 GHA workflow가 안전하게 AWS resource에 접근하고, fork PR·임의 branch 실행은 차단.
**A (행동)**:
- IAM Identity Provider `token.actions.githubusercontent.com` 등록.
- `gha-deploy-role` 신뢰정책의 `sub` 조건으로 `repo:Third-tool/third-tool:ref:refs/heads/main` 잠금.
- workflow `permissions: id-token: write` 추가.
- `aws-actions/configure-aws-credentials@v4`에 `role-to-assume` + `audience` 세팅.
- `vars.AWS_ACCOUNT_ID` 미설정 시 fail-fast 셋업 검증 step.
**R (결과)**: STS 1시간 TTL 임시 자격증명 자동 발급. long-lived key 폐기. fork PR·다른 branch 배포 시도 차단.

**Trade-off**: EC2 컨테이너 내부 S3 접근용 `AWS_ACCESS_KEY_ID` env는 transitional 유지 (ECS Task Role 이행 시 일괄 제거) — 단계적 이행 채택.

**지표**: long-lived key 노출 표면 → 0.

**참조**: `docs/adr/ADR013-gha-oidc-assume-role.md` · `.github/workflows/dev-cicd.yml` · Story-046

**상태**: `[ ] 후보  [ ] 선정  [ ] 보류`

## [0.0.1v-02] VPC 3-layer 네트워크 설계  `[infra-deployment]`

**훅**: 10.0.0.0/16 위에 2 AZ × 3-layer subnet + 단일 NAT로 시작 (스타트업 스코프 무낭비 설계)

**S (상황)**: 새 계정에 VPC 신설. Public/Private/DB 3계층 격리 필요. 초기 트래픽 낮아 이중 NAT는 과잉.
**T (과제)**: 확장 여지 있으면서 초기 비용 최소화. multi-AZ · 보안 격리 · IGW/NAT 통제.
**A (행동)**:
- CIDR 10.0.0.0/16 · 2 AZ × Public/Private/DB × 6 subnet.
- Public subnet에만 IGW route. Private/DB는 NAT 경유.
- **단일 NAT** in AZ-a (초기). 이중화는 트래픽 증가 시.
- Security Group per layer.
**R (결과)**: 3-layer 격리 확보. AZ-a NAT 다운 시 AZ-b private subnet outbound 영향 (수용 가능 리스크).

**Trade-off**: NAT 이중화 유예 → 비용 절감 vs SPOF 리스크. 확장 트리거 명시.

**참조**: `docs/adr/ADR015-vpc-3-layer-network-design.md` · Story-048

**상태**: `[ ] 후보  [ ] 선정  [ ] 보류`

## [0.0.1v-03] ECS Task IAM Role 3종 분리  `[auth-security · infra-deployment]`

**훅**: Execution Role · Task Role · GHA Deploy Role을 목적별로 완전 분리 (권한 최소화)

**S (상황)**: ECS 배포 예정. IAM Role 여러 개 관리 필요. 최소 권한 원칙 · 감사·회수 편의.
**T (과제)**: 각 컴포넌트가 필요한 것만 수행하는 Role 설계. GHA는 배포만, Task는 앱 실행만.
**A (행동)**:
- `ecs-execution-role` — ECR pull, CW Logs write만.
- `ecs-task-role` — 앱 실행 중 필요한 AWS resource (S3 특정 prefix, Secrets Manager 특정 ARN)만.
- `gha-deploy-role` — OIDC 기반, ECS Update Service 등 배포 API만.
- 신뢰정책·권한정책 분리.
**R (결과)**: 각 Role 권한 최소화. 유출 시 blast radius 국한. Role별 활동 추적 명확.

**Trade-off**: Role 3개 관리 오버헤드 vs 권한 격리 이점.

**참조**: `docs/adr/ADR014-ecs-task-iam-role-separation.md` · Story-047

## [0.0.1v-04] ALB Listener · Target Group · TLS 1.3  `[infra-deployment]`

**훅**: ALB 1개 공유 + Listener 80→443 리디렉트 + Target Group type=ip + TLS 1.3 강제

**S (상황)**: 앱 앞단 ALB 신설. HTTPS 강제 · 최신 TLS · ECS type=ip 매칭 필요.
**T (과제)**: HTTP → HTTPS 강제, TLS 1.3, ECS와 target 매칭, ACM 인증서.
**A (행동)**:
- Listener :80 → :443 permanent redirect.
- Listener :443 SSL Policy `ELBSecurityPolicy-TLS13-1-2-2021-06` (TLS 1.3+).
- Target Group type=`ip` (Fargate/awsvpc 대응).
- Health check `/health` 경로.
- ACM 인증서 ARN 바인딩.
**R (결과)**: HTTP 자동 리디렉트. TLS 1.2 이하 차단. ECS awsvpc network mode와 매칭.

**Trade-off**: ALB 1개 공유 → 단순함 vs 여러 앱 host-based routing 시 rule 복잡도.

**참조**: `docs/adr/ADR016-alb-listener-target-group.md` · Story-049

## [0.0.1v-05] Spring graceful shutdown + forward-headers  `[infra-deployment · api-contract]`

**훅**: ECS rolling update 시 in-flight 요청 손실 없도록 shutdown 30s + ALB deregistration_delay 30s 매칭

**S (상황)**: Spring Boot 3.x default `shutdown=immediate`. ECS rolling update 중 SIGTERM 즉시 종료 → in-flight 요청 손실.
**T (과제)**: SIGTERM 수신 시 진행 중 요청 완료 대기 후 종료. ALB deregistration_delay와 정합.
**A (행동)**:
- `server.shutdown: graceful`
- `spring.lifecycle.timeout-per-shutdown-phase: 30s`
- ALB Target Group `deregistration_delay: 30s` (ADR016과 매칭)
- `forward-headers-strategy=native` — ALB X-Forwarded-* 신뢰
**R (결과)**: rolling update 중 요청 손실 0. 클라이언트 IP·프로토콜 정확히 인식.

**Trade-off**: 로컬·dev에서 30s 대기 답답 vs 운영 일관성. 운영 일관성 우선.

**참조**: `docs/adr/ADR017-spring-forward-headers-graceful-shutdown.md` · Story-050

**상태**: `[ ] 후보  [ ] 선정  [ ] 보류`

## [0.0.1v-06] RDS MySQL prod 셋업  `[database · infra-deployment]`

**훅**: 스타트업 스코프에 맞춘 single-AZ + db.t4g.micro + utf8mb4 + Asia/Seoul 표준화

**S (상황)**: prod DB 신설. 초기 트래픽 낮음. multi-AZ 비용 부담. 한국 시간대·이모지 저장 필요.
**T (과제)**: 최소 비용으로 시작하되 utf8mb4 · timezone · timezone-aware timestamp 셋업.
**A (행동)**:
- `db.t4g.micro` single-AZ (ARM · 무료 tier 근접)
- charset `utf8mb4` · collation `utf8mb4_unicode_ci`
- `time_zone = 'Asia/Seoul'`
- parameter group 별도 (기본값 override 관리)
- 백업 · Point-in-Time Recovery 활성화
**R (결과)**: 이모지 저장 가능. 한국 시간대 일관. 백업 자동. 초기 비용 최소.

**Trade-off**: single-AZ → SPOF. 트래픽 증가 시 multi-AZ · read replica 이관 예정.

**참조**: `docs/adr/ADR018-rds-mysql-single-az-prod.md` · Story-051

**상태**: `[ ] 후보  [ ] 선정  [ ] 보류`

## [0.0.1v-07] Secrets Manager 명명 · Task Role scope  `[auth-security · infra-deployment]`

**훅**: 5종 비밀 · env-prefix 격리 · Task Role Resource ARN scope로 blast radius 국한

**S (상황)**: JWT_SECRET, DB_PASSWORD, KAKAO_*, NAVER_* 등 비밀 여러 개. AWS Secrets Manager 도입. Task Role이 모든 시크릿 읽으면 유출 시 폭발.
**T (과제)**: 각 비밀 명명 표준 · env(dev/prod) 격리 · Task Role은 해당 env 비밀만 접근.
**A (행동)**:
- 명명 규칙 `third-tool/{env}/{purpose}` (예: `third-tool/prod/jwt-secret`)
- `ecs-task-role`의 SecretsManager 권한을 특정 ARN 배열로 scope
- env-prefix로 논리적 격리
**R (결과)**: env 간 시크릿 접근 불가. Task Role 유출 시 blast radius = 해당 env 비밀만.

**Trade-off**: ARN 개별 관리 오버헤드 vs 유출 방지.

**참조**: `docs/adr/ADR019-secrets-manager-naming-and-task-role-scope.md` · Story-052

**상태**: `[ ] 후보  [ ] 선정  [ ] 보류`

## [0.0.1v-08] 운영 컨테이너 base image 선정  `[infra-deployment]`

**훅**: Distroless는 보류하고 `eclipse-temurin:21-jre-alpine`으로 균형점 채택

**S (상황)**: Docker base image 선택. Distroless 유혹 (최소 표면) vs debug 편의 (shell 필요).
**T (과제)**: 이미지 크기·보안·운영편의 균형. Java 21 지원.
**A (행동)**:
- 후보: `distroless/java21` · `openjdk:21-jre-slim` · `eclipse-temurin:21-jre-alpine`
- alpine 채택 — musl libc 이슈 없이 Java 정상 동작 · shell 있음 · 이미지 작음 (~180MB)
- Distroless는 보류 (shell 없어 트러블슈팅 어려움, 초기 단계엔 부담)
- multi-stage build로 host gradle 결과 격리
**R (결과)**: 이미지 ~180MB. shell 있어 컨테이너 진입 트러블슈팅 가능. 재검토 트리거 명시.

**Trade-off**: alpine musl libc 잠재 이슈 vs Distroless 학습곡선. 알려진 검증 image로 안전 우선.

**참조**: `docs/adr/ADR012.md` · Story 1-1

**상태**: `[ ] 후보  [ ] 선정  [ ] 보류`
